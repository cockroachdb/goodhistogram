# datatest — cross-language conformance scenarios

This directory pins the behavior of goodhistogram so the **Go** implementation
(`go/`) and the **Rust** implementation (`rust/`) can never silently drift apart.

Each `*.txt` file is one self-contained scenario. Both language test suites read
the same files and check their implementation reproduces them.

```
                 Go implementation  ← source of truth
                        │
   go test -rewrite     │ generates the golden section
                        ▼
             datatest/<scenario>.txt
                   │              │
   Go test suite   │              │   Rust test suite
   regenerates &   │              │   parses & replays,
   checks current  ▼              ▼   compares to golden
     go/datatest_test.go   rust/tests/datatest.rs
```

## File format

A scenario has two halves. Everything above the marker is **hand-authored
input**; everything below is **generated golden output** — don't edit it.

```
# Free-text description of the scenario.

lo 1000                 # tracked-range lower bound
hi 1000000000           # tracked-range upper bound
error_bound 0.1         # selects the Prometheus schema (bucket granularity)
values 1500 20000 ...   # the int64 values to record (may be empty)

# --- generated by `go test ./go/ -run TestDatatest -rewrite`; do not edit below ---
# TYPE goodhistogram histogram
goodhistogram_bucket{le="1024"} 0
...
goodhistogram_bucket{le="+Inf"} 5
goodhistogram_sum 92396500
goodhistogram_count 5
quantile 0 1448.15...
quantile 0.25 ...
...
quantile 1 ...
```

The golden output is:

- **The classic OpenMetrics exposition** — cumulative `_bucket{le=...}` counts
  ending in `+Inf`, plus `_sum` and `_count`. Zero and underflow observations
  sit below every finite bucket, so they are folded into every bucket's
  cumulative count; overflow observations appear only in `+Inf`. `_sum` is the
  raw recorded sum in the histogram's own units.
- **Quantiles** at 0, .25, .5, .75, .9, .95, .99, .9999, .99999, 1 (min, p25,
  median, p75, p90, p95, p99, p99.99, p99.999, max).

### Scope

The fixtures pin the **classic (le-bucket) projection** of the histogram. The
native/exponential encoding (Prometheus native histogram spans/deltas) is *not*
captured here.

## The source-of-truth rule

**Go owns the golden.** Behavior changes land in Go first; you then regenerate
and the Rust side must conform.

- **Go** (`go/datatest_test.go`) replays the recorded values against the live Go
  implementation and checks it reproduces the golden. `-rewrite` regenerates the
  golden section (Go only).
- **Rust** (`rust/tests/datatest.rs`) replays the recorded values against the
  Rust crate and checks it reproduces the golden. It never regenerates.

Both suites compare the same way: exact for bucket counts, sum, and count;
bucket boundaries and quantiles within a small relative tolerance (1e-9 and
1e-6). The tolerance absorbs last-bit differences between math libraries — both
across languages (Go vs Rust) and across platforms (e.g. the arm64 dev machines
vs the amd64 CI runners), which is why the golden is not compared byte for byte.

So: change Go behavior → the Go suite forces a `-rewrite`; forget to update Rust
(or introduce a Rust bug) → the Rust suite fails against the committed golden.

## Regenerating

From the repo root, after any change that affects bucketing or quantiles:

```
go test ./go/ -run TestDatatest -rewrite
```

Review the diff, then run both suites (`go test ./go/` and, in `rust/`,
`cargo test`) to confirm they agree.

## Adding a scenario

1. Create `datatest/<name>.txt` with a description and the input section only.
2. Run the `-rewrite` command above to fill in the golden section.
3. Commit. Both suites pick it up automatically (the files are globbed).

Keep hand-authored scenarios small and readable; large full-range cases are
useful for breadth but are machine goldens, not meant to be read by eye.
