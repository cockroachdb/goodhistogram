# Conformance test data

This directory provides a portable, human-readable contract for
goodhistogram implementations. Go owns and regenerates the golden output;
other implementations can replay the same scenarios and compare their results.

Each `*.txt` file is a self-contained scenario with two sections. The first is
hand-authored input containing histogram parameters and recorded values. The
second is generated output containing the classic Prometheus buckets, count,
sum, schema, the zero/underflow/overflow counters, the native (sparse)
Prometheus export, representative quantiles, and the snapshot's JSON encoding.
Every scalar line appears exactly once, and the quantile lines cover the same
fixed set of quantiles in every file.

```text
lo 1000
hi 1000000000
error_bound 0.1
values 1500 20000 750000

# --- generated by `go test ./internal/ -run TestDatatest -rewrite`; do not edit below ---
# TYPE goodhistogram histogram
goodhistogram_bucket{le="1024"} 0
...
goodhistogram_bucket{le="+Inf"} 3
goodhistogram_sum 771500
goodhistogram_count 3
schema 3
zero_count 0
underflow 0
overflow 0
native_zero_threshold 5e-324
native_zero_count 0
native_spans 85:1 29:1 41:1
native_deltas 1 0 0
quantile 0 1448.1546878700494
...
snapshot_json {"prometheus_schema":3,"lowest_trackable":1000,...,"total_sum":771500}
```

`Lo` and `Hi` only select the lowest and highest Prometheus buckets. Like a
Prometheus bucket's bounds, `Lo` is exclusive and `Hi` inclusive: the lowest
bucket holds values just above `Lo`, and the highest holds `Hi`. Bucket labels,
quantiles, and clamps use those buckets' real edges, never `Lo` or `Hi`.

Because the classic buckets fold zeros and underflow into the same cumulative
count, the zero, underflow, and overflow counters are pinned separately. The
native export lines give the zero bucket's threshold and count, the positive
spans as `offset:length` pairs, and the delta-encoded bucket counts, in
Prometheus's sparse format. The native export carries zeros (in the zero
bucket) and the in-range buckets only: underflow and overflow have no native
bucket, so they appear only in the sample count, and implementations must not
place them in buckets. Bucket counts, count, sum, schema, the counters, and the
native export are compared exactly.
Bucket boundaries and quantiles use small relative tolerances to absorb
last-bit floating-point differences across platforms and math libraries.

## Snapshot JSON

`snapshot_json` is the snapshot encoded as Go writes it: compact JSON with
the snake_case fields `prometheus_schema`, `lowest_trackable`,
`highest_trackable`, `counts`, `zero_count`, `underflow`, `overflow`,
`total_count`, and `total_sum`. `counts` and `total_sum` are 64-bit integers
encoded as JSON numbers, so readers must not parse them as float64. Unknown
fields are ignored. Go checks its own encoding against this text byte for
byte.
Other implementations should compare by value instead, since float formatting
differs across languages (`1e+16` and `1e16` are the same number):

- **Read:** decode `snapshot_json` and reproduce the same buckets, counters,
  and quantiles from the decoded snapshot.
- **Write:** encoding the replayed snapshot and decoding it again must give
  the same values as decoding `snapshot_json`.

`snapshot_json.cases` is a hand-authored list of `accept` and `reject`
payloads. An implementation must decode every accepted payload into a valid
snapshot and refuse every rejected one: wrong bucket counts for the layout,
inconsistent totals, invalid schemas or bounds, partial snapshots, the old
Go-named format, and non-integer counts. Payloads with unknown extra fields are
accepted.

## Implementations

Go (`internal/datatest_test.go`, `internal/presets_test.go`) regenerates and
checks the goldens. The Rust crate replays them in `rust/tests/datatest.rs` and
`rust/tests/presets.rs` and never regenerates them, so a Go behavior change
forces a `-rewrite`, and a Rust implementation that doesn't follow fails its
suite against the committed goldens. The JSON parts of the contract
(`snapshot_json` and `snapshot_json.cases`) apply to implementations that
serialize snapshots; the Rust crate doesn't, so it skips them.

## Regenerating

To regenerate all scenario and preset goldens from the repository root:

```sh
go test ./internal/ -run 'TestDatatest|TestPresets' -rewrite
```

Review the generated diff, then run `go test ./...` to verify it. Only the
`internal` test package defines `-rewrite`, so pass it with `./internal/`:
`go test ./... -rewrite` still rewrites the goldens but reports the root
package as failing with "flag provided but not defined".

To add a scenario, create `datatest/<name>.txt` with a description and input
section, run the regeneration command, and commit both the input and generated
output. Tests discover scenario files automatically.
